  What the installer does

  The .ps1 is a thin shim — it just checks for Node ≥18, then delegates to npx 
  -y github:JuliusBrussee/caveman, which runs bin/install.js. That Node script
  is where the real action is, and it's not a trivial installer. It:

  - Modifies your Claude Code config — patches ~/.claude/settings.json and
  ~/.claude.json, injects hook entries and statusline config
  - Installs hook files into ~/.claude/hooks/ (downloaded from the repo)
  - Writes a flag file so caveman auto-activates every session without you
  asking
  - Registers MCP servers via claude mcp add
  - Spawns subprocesses — claude plugin install, gemini extensions install, npx 
  skills add, etc.
  - Scans your filesystem for installed editors/extensions (VS Code, Cursor,
  JetBrains)
  - Touches configs for other agents too (opencode, etc.)

  It does do SHA-256 integrity checks on downloaded hooks (good), but the bottom
  line is: this rewrites your agent config and installs always-on hooks, not
  just a single skill file.

  Assessment — this is cleaner than most installers

  A few things stood out as genuinely well-built, not red flags:

  - No network calls in any hook. Nothing phones home. Pricing data is hardcoded
  with a comment, not fetched.
  - No eval, no downloaded-code execution. The one subprocess call is
  execFileSync(node, [stats.js, ...]) — Node executing a bundled script
  directly, not through a shell, so no command-injection surface.
  - Defensive file handling throughout — symlink/junction rejection (O_NOFOLLOW,
  reparse-point checks), 64-byte size caps on flag reads, ANSI/OSC-escape
  stripping in the statusline (so a poisoned flag can't inject terminal escape
  sequences), atomic temp-file writes, and a VALID_MODES whitelist. That's the
  kind of thing a sloppy or malicious project skips.
  - All file ops stay inside ~/.claude (or CLAUDE_CONFIG_DIR), plus reading your
  repo's caveman config and session logs.

  Things to actually weigh (not vulnerabilities, just facts)

  1. It reads your session transcripts (~/.claude/projects/**/*.jsonl) to
  compute token-savings stats. Stays local, but it does parse your conversation
  logs.
  2. It registers a UserPromptSubmit hook that inspects every prompt for trigger
  phrases — benign, but it does see all your input.
  3. The auto-activate flag still changes how I respond (terse "caveman" style)
  every session until you turn it off.
  4. I reviewed main branch HEAD. The installer pins to a specific ref with
  SHA-256 checksums, so what it installs should match — but I haven't
  byte-verified the checksums against these exact files.

  Bottom line

  The hooks are local-only, well-defended, and do what the tool advertises —
  compress output and track stats. No exfiltration, no remote execution, no
  PATH/registry/startup persistence tricks. The realistic "cost" is: it reads
  your local session logs for stats and makes me answer tersely.
