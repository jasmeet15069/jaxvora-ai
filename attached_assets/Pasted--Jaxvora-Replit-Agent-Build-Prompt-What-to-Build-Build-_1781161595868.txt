Build **Jaxvora** — a production-ready, autonomous multi-agent AI platform for Engineering, Data, Security, Career, and Automation workflows.

## Replit-Specific Requirements

- Bind the server to `host="0.0.0.0"` and `port=int(os.environ.get("PORT", 8080))`
- Read all secrets from `os.environ` (not from a `.env` file)
- Use **Neon PostgreSQL** (Replit's built-in): read from `os.environ["DATABASE_URL"]`
- Use **Qdrant Cloud** free tier: read URL from `os.environ["QDRANT_URL"]` and key from `os.environ["QDRANT_API_KEY"]`
- If any API key is missing, that agent must return a graceful mock/placeholder response — **never crash**
- No Docker, no build tools, no React, no Next.js, no Vue

## Agent Communication Rules

- Agents **never call each other directly**
- All inter-agent tasks route through the **Chief Orchestrator**
- Every action passes through: `Orchestrator → Approval Layer → Audit Layer`
- Shared state via: `Event Bus`, `Shared Memory (PostgreSQL)`, `Task Queue`, `MCP Tool Registry`

---

## MCP Tool Registry

Implement these as callable async tools registered in a central `MCPToolRegistry`:

| Tool | Description |
|---|---|
| `file_system` | Read/write files in the workspace |
| `terminal` | Run shell commands safely (sandboxed) |
| `github` | GitHub API: repos, PRs, commits, issues |
| `postgresql` | Execute SQL against the connected DB |
| `qdrant` | Semantic search and upsert |
| `browser` | Fetch and parse web pages |
| `security_scanner` | Static analysis for secrets/vulnerabilities |
| `code_formatter` | Lint and format code (ruff, black, prettier) |

## Memory Layer

**PostgreSQL tables (auto-create on startup):**
```sql
projects (id, name, repo_url, metadata, created_at)
tasks (id, project_id, agent_name, status, input, output, created_at, completed_at)
logs (id, task_id, level, message, timestamp)
audit (id, agent_name, action, payload, approved, timestamp)
agent_history (id, agent_name, task_summary, outcome, timestamp)
```

**Qdrant collections (auto-create on startup):**
- `architecture_knowledge` — system design decisions
- `security_findings` — vulnerabilities, fixes
- `code_fixes` — bug patterns and resolutions
- `org_knowledge` — general organizational context

## FastAPI REST Endpoints

```

GET  /agents                — List all agents + status
GET  /tasks                 — List tasks (filter: status, agent)
```

## Frontend: `index.html`

**Design direction:** Dark command center. Background `#0a0b0f`, primary accent `#6c63ff` (electric violet), secondary `#00d4aa` (teal green). Font: `JetBrains Mono` for data/code, `Inter` for prose. Glassmorphism panels with `backdrop-filter: blur`. Thin violet gradient borders. Subtle scanline/grid texture on the background. The UI should feel like a mission control room for AI agents.

**No React. No Vue. No build tools. Pure HTML/CSS/JS with WebSocket connections.**

### Sections (Sidebar Navigation):

#### 1. Dashboard (default view)
- Project health score (ring chart — pure SVG)
- Security score, Performance score, Test coverage
- Active agents count, Tasks today, Issues found

#### 2. Agent Monitor
- Live grid of all agents showing: name, model, status (`idle` / `running` / `error`), current task
- Status dots pulse green when active
- Click agent → modal with last 5 task summaries

#### 3. Chat Interface
- Natural language input → sends to `POST /chat` and opens `/ws/chat`
- Streaming response from Orchestrator
- Quick-action chips:
  - `Fix all bugs`
  - `Analyze architecture`
  - `Run security audit`
  - `Generate Power BI dashboard`
  - `Create ATS resume`
  - `Optimize database queries`
  - `Review code quality`

#### 4. Live Logs
- Real-time feed from `/ws/logs`
- Colour-coded: INFO (grey), WARN (yellow), ERROR (red), SUCCESS (teal)
- Filter by agent name or log level
- Auto-scroll with pause-on-hover

#### 5. Task Queue
- Three columns: Pending / Running / Completed
- Each task card shows: agent name, short description, elapsed time
- Completed cards show outcome badge (success/failed/skipped)

#### 6. Approval Center
- Cards for tasks pending human approval
- Each card shows: agent, proposed action, diff/output preview
- Approve ✓ / Reject ✗ buttons → calls REST endpoints

#### 7. Analytics
- Agent call count per day (bar chart — pure SVG/Canvas)
- Task success rate

- Estimated time saved

#### 8. Settings
- API key status indicators (DeepSeek, Gemini, Groq, Qdrant)
- Does NOT expose key values — only shows `✓ Connected` or `✗ Missing`

## Autonomous Workflow (Orchestrator Logic)

When a task is received via `/chat`:

1. Chief Orchestrator parses intent and creates an execution plan
2. Project Intelligence Agent builds/updates project context
3. Relevant agents are assigned subtasks in priority order
4. Each agent runs its subtask using MCP tools as needed
5. Code Review and Security agents validate outputs
6. Results are logged to PostgreSQL and vectors stored in Qdrant
7. If human approval is required, task is queued in `audit` table
8. On approval, DevOps/Git actions are executed
9. Outcomes are used to update semantic memory (learning loop)

---

## Startup Behaviour

On `startup` event:
1. Run all `CREATE TABLE IF NOT EXISTS` migrations
2. Create Qdrant collections if they don't exist
3. Register all agents in the agent registry
4. Register all MCP tools
5. Broadcast `system_ready` event to all WebSocket clients

## Quality Rules

- WebSocket manager must handle disconnects gracefully
- No hardcoded API keys anywhere in source code
- All prompts to LLMs must include a system message that identifies the agent role
- DeepSeek base URL: `https://api.deepseek.com` (OpenAI-compatible, use `openai` library with `base_url` override)
